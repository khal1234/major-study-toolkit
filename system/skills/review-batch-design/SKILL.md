# 검수 배치 설계 — 내용 읽기와 구조 읽기는 동시에 못 한다

## 핵심 발견 (2026-08-27)

"내용을 읽는 것"과 "구조 결함을 찾는 것"은 **애초에 사람이 동시에 못 하는 서로 다른
모드**다. 사람에게 "내용도 확인하고 구조도 봐 주세요"라고 한 목록을 넘기면, 둘 중
하나(대개 구조)는 놓친다 — 능력 문제가 아니라 애초에 병렬로 안 되는 일을 병렬로
시킨 것이다.

**따라서 배치 순서를 바꾼다: 구조 검사(기계로 잴 수 있는 것)는 에이전트가 먼저
전부 끝내 두고, 사람에게는 내용만 읽게 넘긴다.** 사람이 두 모드를 오가며 확인하게
만들지 않는다.

## 리뷰 피로 (4회 반복 관측)

검수가 길어질수록 사용자가 사소한 지적을 놓아버린다(뒤로 갈수록 지적이 준다).
이건 사용자의 집중력이 떨어져서지 사소한 게 정말 없어져서가 아니다.

## 체크리스트 (긴 목록을 사람에게 넘기기 전에)

1. 목록 안의 항목 중 **기계로 이미 확인 가능한 것**(형식·좌표·존재 여부·구조적
   일관성)이 섞여 있는가? 있다면 그건 사람에게 안 넘기고 먼저 처리해서 걸러낸다.
2. 남은 것 중 **정말 사람의 판단(느낌·의미·의도)이 필요한 것**만 사람에게 넘긴다.
3. 목록이 길면(대략 10개 이상, 혹은 리뷰 시간이 길어질 것 같으면) 뒤쪽 항목일수록
   더 명확하고 짧게 적는다 — 사람의 집중력이 이미 떨어진 시점이라고 가정한다.
4. 배치를 나눌 수 있으면, 한 번에 다 넘기지 말고 끊어서 넘기는 것도 고려한다
   (오늘 확인된 원리: 세션이 길어질수록 판단 품질이 떨어지는 것과 같은 축).
