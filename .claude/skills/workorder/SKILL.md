# 워크오더 (2026-09-11 AGENTS.md 에서 옮김)

## 워크오더 — 자기 규율용 작업 기록

Codex 분업이 꺼지면서(2026-07-27) '핸드오프' 목적은 사라졌다. 하지만 워크오더의 **품질 규율**은
단독 작업에도 그대로 유효하다 — 큰 작업은 계획을 파일에 박아두고 그 계획으로 스스로 검증받는다.

- **큰 작업**(챕터 재검·삽화 배치·구조 변경)은 `data/<과목>/<작업명>.workorder.md`에
  범위·수용 기준·**항목별 `판정:`**(규칙 8)·**기준 커밋**을 적는다.
- 완료를 주장하기 전 `python tools/verify_workorder.py <문서>`가 **exit 0** 이어야 한다
  (아래 '워크오더 수용 게이트'가 정본).
- 노랑 구역 판단을 했으면 `## 자율 판단 기록`을 남긴다(규칙 10) — *무엇을 / 근거 / 되돌리는 법*.
- **자잘한 단발 수정까지 워크오더로 만들 필요는 없다.** 부류 전수 감사가 붙는 규모일 때 쓴다.
- 애매하면 진행하지 말고 **사용자에게 먼저 묻는다** — 특히 콘텐츠 문구·삭제가 필요해 보일 때.
- 과거 두-에이전트 핸드오프 프로토콜·Codex 진행 기록 형식은
  `docs/archive/codex-workflow.archived.md`에 보관돼 있다(재분업 시 복원).

### 작업지시서 형식

새 workorder 맨 위에는 아래 항목을 짧게 둔다. 긴 배경 설명은 그 아래에만.

```md
## 기준 커밋          ← 작업 시작 시점 sha (verify_workorder가 이걸로 실제 변경을 대조한다)
## 실행 범위
## 수정 가능 파일
## 완료 기준          ← 산문이 아니라 **exit 0이어야 하는 명령**으로 적는다
## 금지 사항·검증 방법
## 항목별 판정        ← 항목마다 `판정: 수용/반박/조건부` + 근거 한 줄
## 자율 판단 기록      ← 노랑 구역 판단을 했다면 (무엇을/근거/되돌리는 법)
## 진행 기록
```

**완료 기준은 검증 가능해야 한다.** "삽화가 규격을 통과한다"는 누구도 판정할 수 없다.
대신 이렇게 적는다:

```md
## 완료 기준
- `python tools/verify_workorder.py data/열역학/<작업명>.workorder.md` exit 0
- `python tools/audit_content.py` 사각지대 0건
```

## 워크오더 수용 게이트 — `tools/verify_workorder.py`

"완료했다"고 쓰기 **전에** 스스로 돌린다. **exit 0 이 아니면 완료라고 쓰지 않는다.**

```
python tools/verify_workorder.py data/<과목>/<작업명>.workorder.md
```

검사: ① 모든 항목에 `판정:` ② **기록한 변경 파일이 실제로 바뀌었는가** ③ 미신고 변경 ④ 노랑 판단이
있으면 `## 자율 판단 기록` 존재 ⑤ 빌드 통과 ⑥ 회귀 통과 ⑦ **`## 완료 기준` 의 명령을 실제로 돌려
exit 0 인가**(자기 호출과 ⑤·⑥이 이미 돌린 것은 건너뛴다).

- **②가 핵심이다** — "수정 완료"라고 적었는데 파일은 그대로인 사고가 최소 3회 났다.
  **진행 기록은 증거가 아니다. git diff 가 증거다.**
- ⑦은 2026-08-07 신설. 형식은 *[발화 생략]* 을 요구해 왔는데
  **게이트가 그 절을 읽지도 않았다** — 수용 게이트가 자기가 요구한 것을 검사하지 않은 자리다.
  절이 없거나 실행 가능한 명령이 하나도 없으면 실패다(경고로 열어 두면 더미에 묻힌다).
- **`> 상태: 종결` 은 게이트에 아무 힘이 없다** — 한때 ⑦을 건너뛰게 했다가 같은 날 되돌렸다(완료 직전에
  한 줄 적으면 게이트가 꺼지는 길이었다). 사람이 읽는 표시로는 써도 된다.
  잠금 `test_completion_criteria_are_executed`.
- **끝난 워크오더는 다시 돌리지 않는다**(판정 2026-08-08). 이 게이트는 `기준 커밋 → 지금` 을 비교하는데
  위쪽 끝이 「지금」이라 창이 안 닫힌다 — 끝난 뒤 들어온 남의 배치가 계속 쌓인다(실측: 옛 워크오더 하나를
  지금 돌리면 기준 이후 변경 163건 중 거의 전부가 다른 챕터). **봉인 장치는 짓지 않는다** — 아무도 옛
  워크오더를 안 돌리기 때문이다(`close_report` 도 빌드도 *변경된* 워크오더만 본다). 상시 보증은
  빌드·회귀·`close_report` 가 하고, 워크오더는 **완료를 한 번 수락하는 게이트**다.
  되짚을 이유가 생기면 `docs/proposal-workorder-seal.md` 를 꺼낸다.

워크오더에는 **작업 시작 시점의 커밋**을 적어 둔다(없으면 `HEAD~1` 기준이라 부정확해진다):

```md
## 기준 커밋
<작업 시작 시점 sha>
```
