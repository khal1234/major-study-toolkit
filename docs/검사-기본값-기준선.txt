# 「기본값 뒤집기」의 기준선 — 2026-08-15에 **이미 있던** 검사 키 목록.
#
# ★ 무엇을 정하나: `is_strict_chapter()` 의 **기본값**이다.
#   · 여기 적힌 키(= 옛 키)  → 예전 그대로 **opt-in**. 그 과목이 `strictChapters` 에
#     챕터를 올려야 error 가 된다. 이미 밀린 정리분이 과목마다 다르기 때문이다.
#   · 여기 **없는** 키(= 새 키) → **전 과목·전 챕터 기본 error.** 안 켜려면 그 과목
#     `index.json` 의 `strictWaivers` 에 **사유와 함께** 적는다(사유 없으면 면제로 안 친다).
#
# 왜 이렇게 갈랐나(사용자 지적 2026-08-15) — 과목이 여러 개일 때 새 검사 하나가 전 과목 선언을 요구하면, 한 과목만 고치려 해도 나머지 전부를 건드려야 하는 부담이 있다는 지적.
#   승격이 **과목별 선언**이라, 검사를 하나 만들면 과목 수만큼 선언을 적어야 켜졌다.
#   실측: 과목당 선언 키가 39~51개. 12과목이면 새 검사 하나에 12곳, 30과목이면 30곳이고
#   **빠뜨린 과목은 경고조차 없이 조용히 꺼진 채** 남는다(「폴백으로 하나만 넣어 두기」와 같은 침묵).
#
# ★ 왜 옛 키까지 한꺼번에 안 뒤집었나 — **남의 빌드를 멈추는 승격은 승격이 아니다.**
#   같은 실사고가 이미 있었다(2026-08-02: 한 과목이 ch01~ch03 을 올리자 다른 과목 빌드가 깨졌다).
#   옛 키는 과목마다 밀린 양이 다르므로 그 진도는 `strictChapters` 가 계속 갖는다.
#
# ★ 이 목록은 **늘리지 않는다.** 새 검사를 여기 적으면 그것이 곧 이 조치를 되돌리는 것이다.
#   줄이는 것(= 옛 키를 전 과목이 정리해 기본 error 로 올리는 것)은 언제든 환영이다.
